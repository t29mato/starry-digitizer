        What this page proves. The whole digitizing engine — image
        decoding and fitting, axis calibration, automatic point extraction and
        the conversion of pixels to physical values — runs from the
        starry-digitizer/core entry alone, driven by plain DOM and
        TypeScript. Change notification comes from the
        effect() that entry re-exports, and it drives the
        points / calibration read-outs above by writing into text
        nodes.
      

      

        What it deliberately does not use. No vue import, no
        starry-digitizer default entry, no
        starry-digitizer/vue, and no
        starry-digitizer/styles — a core-only host has no library
        UI, so it needs no library stylesheet. The sibling page (index.html) is the opposite case: the full component mounted from a non-Vue host.
